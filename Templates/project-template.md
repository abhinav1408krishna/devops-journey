## 6. Step-by-Step Implementation Guide

Build the project incrementally. Do not simply provide the complete codebase without explaining how to construct it.

For each implementation step, use the following structure:

### Step [Number] — [Action or Feature]

**Goal:** Explain what this step accomplishes.

**File or Location:** Specify the exact file path, directory, or environment to use.

**What to Write or Configure:**
- Identify the section, configuration, command, or logic to implement.
- Explain its responsibility and how it fits into the project.
- Break complex logic into manageable parts.
- Explain unfamiliar syntax and terminology.
- Include relevant commands or small examples when they help the reader understand the task.

**Implementation Instructions:**
Give ordered instructions for writing or configuring this section. Explain the logic rather than relying on unexplained copy-and-paste code.

**Validation Commands:**
Provide commands to inspect, validate, or test the work completed in this step.

**Expected Result:** Describe the observable result that indicates success.

**Troubleshooting:** Explain likely errors, how to investigate them, and how to recover.

Repeat this section for each file and each meaningful implementation stage until the project is complete. Adapt the subsections to the technology instead of adding irrelevant material.
